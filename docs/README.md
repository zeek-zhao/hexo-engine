## 2. 命名规范（本仓库）

### 2.1 目标格式

```
<前缀>-<两位序号>-<主题>.md      例：URD-01-需求规格.md、SDD-01-概要设计.md、UI-01-原型说明.md
G-<两位序号>-<主题>.md           例：G-01-功能原理解析.md（指南/原理类，建议统一）
```

| 要素 | 规则 |
|---|---|
| 前缀 | `URD`（需求）/ `SDD`（设计）/ `UI`（界面）/ `G`（指南与原理）；全大写 |
| 序号 | 两位数字，同类内递增，不复用 |
| 主题 | 中文短语，不含空格、下划线、日期、版本号（版本写在 frontmatter/文首版本行） |
| 扩展名 | 固定 `.md` |

### 2.2 现状合规性（结合实际情况）

| 文件 | 现状命名 | 是否符合 2.1 | 建议规范名 |
|---|---|---|---|
| URD-01-需求规格.md | 合规 | ✅ | — |
| SDD-01-概要设计.md | 合规 | ✅ | — |
| UI-01-原型说明.md | 合规 | ✅ | — |
| 功能原理解析.md | 无前缀无序号 | ⚠ | `G-01-功能原理解析.md` |
| OB转换与命名指南.md | 无前缀无序号 | ⚠ | `G-02-OB转换与命名指南.md` |
| 功能说明与使用指南.md | 无前缀无序号 | ⚠ | `G-03-功能说明与使用指南.md` |
| SEO-RSS-评论详解.md | 含连字符类名但无序号 | ⚠ | `G-04-SEO-RSS-评论详解.md` |
| PAT替换指南.md | 无前缀无序号 | ⚠ | `G-05-PAT替换指南.md` |

### 2.3 为什么暂不物理重命名/移动

1. **引用完整性**：`AI.md §7`、`URD/SDD/UI` 正文、`功能说明与使用指南.md`、`SEO-RSS-评论详解.md`、工作笔记、历史提交信息里都写死了当前文件名与 `docs/xxx` 路径；改名要一次性同步十余处，漏一处就出现死链。
2. **docs/ 不参与构建**：`hexo generate` 不读 docs/，`check-pages.js`/BDD 也不依赖它，物理整理对线上零收益。
3. **稳定性优先**：这套文档已是多次评审的记录载体，保持路径稳定比格式整齐更重要。

> **如需执行物理归类**，确认后按以下顺序一次性完成（PowerShell/Node 脚本）：
> ① `git mv` 5 份到 `docs/guides/` 并用规范名；② 批量替换全仓 `docs/<旧名>` → `docs/guides/<新名>`（含 AI.md §7 与本文件表格）；③ 全仓 `grep -r '<旧名>'` 应 0 命中；④ 单独提交（不与功能改动混在一起）。

## 4. 单一数据源约定（防双源漂移）

| 事实 | 权威文件 | 其他文件如何引用 |
|---|---|---|
| 需求编号 FR/AC | URD-01 | SDD/AI.md 只写编号与结论，不复述全文 |
