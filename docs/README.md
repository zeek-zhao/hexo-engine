## 2. 命名规范（本仓库）

### 2.1 目标格式

```
<前缀>-<两位序号>-<主题>.md      例：URD-01-需求规格.md、SDD-01-概要设计.md、UI-01-原型说明.md
G-<两位序号>-<主题>.md           例：G-01-功能原理解析.md（指南/原理类）
```

| 要素 | 规则 |
|---|---|
| 前缀 | `URD`（需求）/ `SDD`（设计）/ `UI`（界面）/ `G`（指南与原理）；全大写 |
| 序号 | 两位数字，同类内递增，不复用 |
| 主题 | 中文短语，不含空格、下划线、日期、版本号（版本写在 frontmatter/文首版本行） |
| 扩展名 | 固定 `.md` |
| 目录 | A 类平铺 `docs/`；B、C 类归 `docs/guides/` |

### 2.3 重命名执行记录（2026-11-15）

此前暂缓物理重命名的三条顾虑（引用完整性、docs 不参与构建、路径稳定性）已按一次性原子操作消解：

1. `git mv` 5 份到 `docs/guides/` 并改为规范名；
2. Node 脚本批量替换全仓 `docs/<旧名>` → `docs/guides/<新名>`（含 `AI.md §7`、本文档、URD/SDD/UI、指南正文互相引用）；
3. `tests/bdd-runner.js` 的文档存在性断言同步改为 `guides/G-0N-…`；feature 步骤文本保持稳定不写死文件名；
4. 全仓 `grep` 复核：旧名 0 处裸用（仅存于本表的「由…更名」溯源说明与历史提交信息）。

> docs/ 不参与 `hexo generate`，`check-pages.js`/BDD 只校验文档存在性，因此本次重命名对线上站点零影响。

## 4. 单一数据源约定（防双源漂移）

| 事实 | 权威文件 | 其他文件如何引用 |
|---|---|---|
| 需求编号 FR/AC | `docs/URD-01-需求规格.md` | SDD/AI.md 只写编号与结论，不复述全文 |
| 分类领域映射、图标 | 内容库 `06-分类映射.json`（SOP-06） | 引擎侧 `icons.js`/`collect.js` 运行时读取 |
| frontmatter 与写作规则 | 内容库 SOP-07 | 本仓库 `docs/guides/G-02-OB转换与命名指南.md` 站在引擎视角，不复制 SOP-07 全文 |
| 身份/凭据/门禁基线 | 内容库 SOP-05 §5 | AI.md §8 摘要引用 |
| 版本号 | 各文件文首「版本 vX.Y」行 | 目录/索引只写当前版本，不写历史 |
