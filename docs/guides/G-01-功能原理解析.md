## 0. 全局架构

```
┌─────────────┐  git push   ┌──────────────┐  dispatch(push 触发)  ┌───────────────────┐
│ ai-obsidian │ ──────────▶ │ notify-publish│ ──────────────────▶ │ hexo-engine CI     │
│ (私有内容库) │             │ (AI workflow) │                      │ collect → hexo     │
└─────────────┘             └──────────────┘                      │ check-pages → BDD  │
                                                                  └────────┬──────────┘
                                                                           │ orphan push
                                                                           ▼
                                                                  zeek-zhao.github.io
                                                                  (公开 gh-pages)
                                                                   ▲ 主题 themes/zeek
                                                                   │ 渲染 = EJS 模板 ×
                                                                   │           构建期脚本
                                                          浏览器 ◀─┘ 交互 = main.js（无框架）
```

三层分工：

| 层 | 载体 | 职责 |
|---|---|---|
| 收集层 | `bin/collect.js`（Node，零依赖） | 目录黑名单、双开关门禁、双链消解、abbrlink、search.json、图片拷贝 |
| 渲染层 | hexo 7 + `themes/zeek`（EJS + Stylus→CSS，零主题依赖） | 两级分类、模板、JSON-LD、RSS/sitemap |
| 交互层 | `source/js/main.js`（原生 JS，零框架零依赖） | pjax、⌘K 搜索、播放器、主题、所有增强 |

**设计原则**：主题与交互层零 npm 依赖（构建可复现），重型渲染（mermaid/数学/live2d）全部 CDN 客户端懒加载、失败静默降级。

## 1. 两级分类体系

**原理**：内容库只维护「细分分类」（= 顶层目录名，如 hexo、yocto）；「领域」（8 个）由受控映射表 `06-分类映射.json` 在构建期注入为嵌套分类 `[[领域, 细分]]`。hexo 天然把嵌套分类渲染成 `/categories/领域/细分/` 两层 URL。

**为什么映射放内容库而不是引擎**：领域归属是「内容策展」决策，跟内容版本走（改映射 = 改内容库一次 push，引擎不用发版）；映射同文件还承载分类图标（icons/groupIcons）。

**实现链**：collect.js `groupOf()` 注入 → helpers.js `catTree(site)` 把扁平 site.categories 组装成树（roots/childrenOf/byLeaf/rootOf）→ layout.ejs 侧栏三级折叠（领域→细分→文章）、index.ejs 8 领域卡、category.ejs 面包屑上溯。

**已知坑**：hexo 分类页 `page.category` 是**名称字符串**不是对象，必须 `site.categories.findOne({name})` 回查（commit c9dae0e）。

## 2. Obsidian 方言转换

**原理**：两个 hexo 脚本滤镜（构建期跑一次，浏览器零成本）：

- `obsidian.js` `before_post_render`（优先级 **1**）：mermaid 围栏提前转为 `<div class="mermaid>`（否则被 hexo 代码块滤镜降级为 plaintext 代码块）、==高亮==→`<mark>`、%%注释%%删除、脚注重组、callout 别名归一（12 类型）→ `after_post_render` 把 blockquote 转成 callout div。
- 所有正则**围栏感知**（fence 长度配对）且排除行内代码/嵌套括号，教学文档里「讲语法本身」的示例不会误伤。

**质检**：`check-pages.js` 逐篇比对「源文件语法特征数 == HTML 元素数」（callout/mark/脚注/checkbox/mermaid…），对不上 CI 直接红。

## 3. ⌘K 全文搜索

**数据**：collect.js 每篇生成 `{title, url, date, description, tags, categories, group, text}`，`text` = 正文剥图片/代码标记后压缩 1200 字符；全站单文件 `search.json`（约 2.4MB，gzip 后线 上传输约 600KB），**首次打开搜索面板才 fetch，之后内存复用**。

**匹配**：多关键词 AND，命中域 = 标题+描述+标签+分类+正文；标题命中排前；片段展示取首个关键词 ±30/70 字符上下文；**第九轮起命中词以 `<mark class=hl>` 高亮**（先转义再包裹，防 XSS）。

**参考**：这种「构建期生成静态索引 + 客户端过滤」是静态博客主流方案（hexo-generator-search 同思路）；万篇级以上才需要引入 lunr/minisearch 这类倒排索引。

## 4. pjax 站内导航 + 电台播放器（第九轮）

### 4.1 为什么需要 pjax

浏览器整页刷新必然终止 `<audio>`。要让「站内点来点去音乐不停」，唯一纯静态方案是**不刷新页面**：拦截同源链接 → `fetch` 新页 HTML → `DOMParser` 解析 → 替换 `#view`（正文）/`#sideTree`（侧栏树）/`#toc`（目录）/`document.title`/`body[data-page]` → 重跑 `initPage()`（TOC spy、代码复制、折叠默认、归档筛选、KaTeX/mermaid/reveal、giscus 全部页面级重初始化）→ `pushState` 进历史栈，`popstate` 回退同样走 fetch。

**降级**：fetch 失败 / 修饰键点击 / 中键 / target=_blank / 站外链接 → 原生整页跳转，功能无损。

**代价与对策**：main.js 必须把「全局一次绑定」与「页面级初始化」严格分层（本次重构的核心）；滚动监听等资源在每次导航后由 `spyCleanups` 数组统一释放，防泄漏。

### 4.2 播放器

**数据**：543 集节目单在构建期抓取（网易云 `api/dj/program/byradio`，需 `Referer` + `os=pc` Cookie 头，浏览器 CORS 直连不可行 → 落成静态 `source/bgm/playlist.json`）。

**播放源**：每集 `https://music.163.com/song/media/outer/url?id=<songId>.mp3`（302 到 126.net CDN）。注意：这是网易的**非官方外链**，可能限流/失效/部分环境 302 落到 http 触发 mixed-content——播放器 error 事件会把该集标灰，换下一集。

**功能**：顺序播放 / 单曲循环（ended 事件分派）、⏮⏭、列表点播、进度条、模式记忆。`localStorage['bgm-state']` 每 5 秒及暂停/切歌时存 `{i, t, mode, playing}`；**整页刷新后**自动定位到上次曲目+进度，因浏览器自动播放策略不能自动响，🎵 按钮呼吸动画提示「点我续播」；**站内导航**（pjax）音频对象根本不销毁，自然连续。

## 6. 评论 giscus

**原理**：giscus 是 GitHub App，把仓库 Discussions 当评论数据库。文章页挂一个懒加载 iframe（进入视口 400px 才加载 `client.js`），`data-mapping: pathname` 把 URL 路径映射到 Discussion thread。主题切换通过 `postMessage` 通知 iframe 换肤。

**前置**：①仓库开 Discussions（已开，Announcements 分类）②**安装 giscus App 到 zeek-zhao.github.io**（人工操作，装完即恢复）③repoId/categoryId 是公开 widget 参数非密钥。

**参考**：giscus.app；同类方案 utterances（用 Issues，串楼体验差些）。

## 7. 门禁与测试体系

| 层 | 工具 | 断言规模 |
|---|---|---|
| 收集门禁 | collect.js 6 类跳过 + report | 1155 进 / 全库扫描 |
| 渲染体检 | check-pages.js（零依赖 Node） | 11500+ 项/次，FAIL 阻断发布 |
| BDD | bdd-runner.js（自研 Gherkin 子集）+ 12+ feature / 35+ 场景（以 npm run test:bdd 实时输出为准），deploy.yml 里发布前必跑 |
| 泄漏防线 | 黑名单目录 + 体检断言 + 匿名搜索黑名单词 0 命中 | 未发布内容三重保险 |

**为什么自研 BDD runner 而不用 cucumber**：断言对象是静态 HTML 字符串，不需要浏览器驱动；全部场景的步骤全是字符串/正则断言，自研 90 行 runner（ADR-8）换来零依赖与 CI 秒级执行。
