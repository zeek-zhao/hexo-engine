# G-06-博客写作风格（去 AI 味规则）

> 引擎侧索引副本。规则**权威源**是内容库 `ai-obsidian/90-OB工程管理/方案/08-博客写作去AI味规则.md`（OB-ENG-SOP-08），本文件只做引擎侧速查，避免双源漂移。改写文章前请先读权威源全文。
> 配套：G-02《OB转换与命名指南》管格式转换，本文件管写成什么样。

## 一句话原则

文章要像**真实工程师写给同路人的复盘**，不是 AI 教学文档。中度改写：保技术信息，改语气句式结构，删套话模板块；不虚构经历，只在已有事实处用第一人称。

## 硬指标速查

| 维度 | 规则 |
|------|------|
| 开头 | 1–2 句说清解决什么/为什么写，不写 README 式介绍 |
| 结尾 | 停在最后结论或下一步，不写"总结全文/希望有帮助" |
| 单句 | ≤ 40 字，超就断句；连续 3 句同结构必改 |
| 段落 | 2–5 句、单意思；手机 ≤ 5 行 |
| bullet | 连续 ≤ 5 条，超过回到散文 |
| 标题 | 结论式（"Cyber RT 为什么用共享内存"），不用"概述/简介" |
| 语气 | 平述、克制、有判断；不教学敬语、不营销感叹 |

## 禁用词（命中即改）

- 教学：`本节目标`/`学习目标`/`学习提示`/`小贴士`/`划重点`
- 总结：`综上所述`/`总而言之`/`由此可见`/`值得注意的是`/`需要注意的是`
- 排比：`首先…其次…最后`/`不仅…而且…更是`
- 铺垫：`随着…的发展`/`在当今…的时代`
- 黑话：`赋能`/`抓手`/`闭环`/`底层逻辑`/`颗粒度`

## 引擎侧注意

- **块级 AI 痕迹**（`本节目标` callout、页脚 AI 流水线字样）由主题/模板修，不逐篇改；逐篇改的是正文语气与结构。
- **代码块语言**按实际标注（yaml/cpp/python/text/bash），别全标 bash——check-pages.js 会按语言断言。
- **改标题改 abbrlink**：短链 = crc32(旧 title)，改中文标题会变 URL，可能影响外链与 giscus 路径。样稿阶段先不动 title frontmatter，只改正文 H1 时须评估。
- **跨篇重复数据**：主篇详写 + 他篇一句带过并链回主篇。

## 自检清单

改写完逐条过 SOP-08 §8（无禁用词/无三连排比/段落合规/代码块语言正确/开头非 README/有第一人称判断/标题结论式/重复数据已收敛），再跑 `npm run build` + `npm run test:bdd`。

## 改写工作流

全库改写走三阶段 skill（见内容库 `90-OB工程管理/skills/`）：`07-audit-confirm-rewrite`（审计→人工确认→改写总编排）→ `08-audit-report`（出审计清单）→ `09-deai-rewrite`（执行改写）。铁律：未经人工确认不得改正文。
