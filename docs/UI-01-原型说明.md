## 2 视图映射表（原型 hash ↔ 线上 URL）

原型是 hash 路由 SPA；线上是多页站点（MPA），5 个真实页面 + 404。「改造对照」视图是原型专属，不进线上。

| 原型路由 | 原型视图 | 线上 URL | 承载 |
|---|---|---|---|
| `#/home` | 首页（hero + 精选 + 热门 + 最近更新 + 分类卡片） | `/` | 主题 `index.ejs`（取代 collect.js 停用的动态主页） |
| `#/archive`（`?cat=` `?tag=`） | 归档（分组 + 真过滤） | `/archives/` | 主题 `archive.ejs` |
| `#/tags` | 标签云 | `/tags/` | 主题标签视图（collect.js tags/categories 统计职责并入呈现） |
| `#/article/:id` | 文章页 | `/posts/:abbrlink.html` | 主题 `post.ejs`；abbrlink = crc32(title) |
| `#/about` | 关于（PROFILE 数据驱动） | `/about/` | 主题 `page.ejs` |
| `#/compare` | 标题去编号改造对照 | **不进线上** | 原型专属演示页 |
| 未知 hash | 404 视图 | `/404.html` | 主题 `404.ejs` |

分类树侧栏、TOC、顶栏为全视图共用骨架，线上以 partials 实现。

## 5 原型与线上差异（有意为之，非遗漏）

### 5.1 定稿后追加：两级分类（OB-ENG-SOP-06，2026-11-14）

原型定稿时侧栏是 46 个扁平分类组，人反馈「目录太长、没有二级分级」。实施后的线上结构：

| 层 | 内容 | 数据来源 |
|---|---|---|
| 一级（领域） | 8 个：工程规范 / DevOps 与 CI / 自托管服务 / 知识工具 / 技能专项 / 操作系统与机器人 / 编程语言 / 健身 | `content/90-OB工程管理/方案/06-分类映射.json`（受控文档） |
| 二级（细分） | 原 46 个分类，归属按映射表 | 同上，collect.js v7 构建期注入 `categories: [[领域, 细分]]` |
| 三级（文章） | 该细分分类下的文章链接 | `catTree(site)` helper 的 `byLeaf` |

- **侧栏**：`sidegroup`（领域，默认折叠）→ `sg-sub`（细分，默认折叠，▶ 单独展开）→ `sg-items2`（文章）。分类页/文章页只渲染当前领域一组（其余 7 组不渲染）。
- **首页**：8 张领域卡替代 46 张分类卡；**归档页**：按领域 `archdomain` 分组 + 内层按细分 `<details>`；**统计页**：`catgroup` 两级 `<details>`；**面包屑**：首页 / 分类 / 领域 / 细分 / 标题。
- **维护约束**：vault 里 frontmatter 仍只写单一细分分类（写作习惯不变）；领域归属只在映射 JSON 里改，collect.js 与主题模板都不用动；映射缺失时构建告警并 fallback「其他」。细分分类 URL 保持 `/categories/<领域>/<细分>/` 两层。
- 主题实现要点：hexo 分类页 `page.category` 是**名称字符串**，必须 `site.categories.findOne({name})` 回查对象才能沿 `parent` 上溯（layout.ejs `activeRootId`、category.ejs 面包屑均按此处理）。
